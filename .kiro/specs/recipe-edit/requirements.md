# recipe-edit（Phase 5）の要件定義

## 背景

写真から読み取ったレシピは、確認画面（S-04c）で「読み取り間違いを見つける」ところまではできるが、**見つけた間違いを直す手段がタイトルしか無い**（`✎ 改題`。Phase 3 Req7）。確認画面の目的は「間違いを見つけて直す」ことなので、**直す導線が無いのは機能的な欠落**として Phase 3 から持ち越されてきた（recipe-view design.md 6.8）。

このフェーズで S-05（レシピ編集）を作り、**材料・分量・カテゴリ・作り方**を直せるようにする。あわせて、Phase 3 から保留していた **S-04 の `編集` と、確認バーの「編集する」を戻す**。これで `REQUIREMENTS.md` 3章の MVP スコープが全部揃う。

## 前提（確定済み。蒸し返さない）

- **視覚仕様は `Design_引き継ぎ資料/design_handoff_recipe_design_system/README.md` が正。** 正本の HTML は `Recipe Design System v2.dc.html`（緑基調の無印版は履歴。使わない）
- **デザイントークンは `app/globals.css` の `@theme` に投入済み。値を推測で変えない**
- **「移動 / 操作 / 絞り込み」を面の有無で描き分ける。この3種以外の見た目を足さない**（recipe-view design.md 6.2）
- **レシピは必ず `userId` でスコープする**（`.kiro/steering/architecture.md`）
- **この画面は単一カラムのまま max-width 640px で中央寄せ**（引き継ぎ資料 Interactions「レスポンシブ」。1列/3列になるのは一覧だけ）
- **詳細画面と編集画面は別画面**（`REQUIREMENTS.md` 4.7 / `UI_DESIGN.md` 4章 決定3）
- **タイトルは S-05 では直さない。** S-04 の `✎ 改題` だけで直す（`REQUIREMENTS.md` 4.7 の線引き。2026-08-24 決定）
- **材料行は「材料名が左・分量が右」**（recipe-view design.md 6.5。資料の編集画面も同じ並び）

## 要件

### Req1: S-04 と確認画面から編集画面へ入れる

`UI_DESIGN.md` 2章「S-04 通常モードからも『編集』で S-05 に入れる」/ S-04c「編集 → S-05」。決定②。

- **S-04 通常モードのヘッダー上段の右端に `編集`** を出す。見た目は「操作」＝枠線ボタン（左の `← 一覧` と並ぶ）
- **確認モードの最下部バーに「編集する」（副次）** を出す。並びは「この内容で決定」（主要）→「編集する」（副次）
- **確認モードではヘッダー上段を出さない**（今のまま。Phase 3・4 と同じ）
- 押すと `/recipes/<id>/edit` へ移動する

**受け入れ基準**

- [ ] 通常モードのヘッダー上段に、左 `← 一覧`・右 `編集` が出る
- [ ] 確認モード（`?confirm=1`）ではヘッダー上段が出ない（`← 一覧` も `編集` も無い）
- [ ] 確認モードの最下部バーに「この内容で決定」と「編集する」がこの順で縦に並ぶ
- [ ] `編集` / 「編集する」を押すと `/recipes/<id>/edit` が開く
- [ ] S-04 に削除の導線が無い

### Req2: 材料を直せる（S-05「材料」の節）

`REQUIREMENTS.md` 4.7「材料・分量・カテゴリ…を編集できる」/ `UI_DESIGN.md` S-05 / 引き継ぎ資料「Screens 6」。

- 材料1つ＝**行カード1枚**。1段目に材料名・分量、2段目にカテゴリ（プルダウン）・削除
- カテゴリの選択肢は **野菜 / 調味料 / その他**（この順）
- 節の末尾に「**＋ 行を追加**」。押すと末尾に空の行カードが1枚増える。**追加した行のカテゴリは「その他」**
- 並びは保存済みの `order` の順。**並べ替えはできない**（決定①）
- 開いた時点で、保存済みの材料・分量・カテゴリが入っている

**受け入れ基準**

- [ ] 開くと、S-04 と同じ順で全材料の行カードが並び、値が入っている
- [ ] 材料名・分量を書き換えられる。カテゴリを選び直せる
- [ ] 「＋ 行を追加」で末尾に空の行が増え、カテゴリが「その他」になっている
- [ ] 行の削除ができる（Req4）

### Req3: 作り方（手順）を直せる（S-05「作り方」の節）

決定①。**資料に視覚仕様が無いので既存の部品で組む。**

- 材料の節の**下**に「作り方」の節を置く
- 手順1つ＝**カード1枚**: 手順番号の丸 ＋ 本文の入力欄（**複数行**）＋ 削除
- 節の末尾に「**＋ 手順を追加**」。押すと末尾に空の手順カードが1枚増える
- **並べ替えはできない。** できるのは本文の修正・削除・末尾への追加だけ
- 手順番号は画面上の並び順（1から）。削除すると詰め直される

**受け入れ基準**

- [ ] 材料の節の下に「作り方」の節があり、保存済みの手順が順に並んでいる
- [ ] 手順の本文を書き換えられる。改行を含められる
- [ ] 「＋ 手順を追加」で末尾に空の手順が増え、番号が続き番号になる
- [ ] 途中の手順を消すと、以降の番号が詰まる

### Req4: 行を消すときは確認を挟む

引き継ぎ資料 Interactions「削除: 常に確認ダイアログを経由」/「確認ダイアログ」（見本の文言が「この行を削除」）。

- 材料の行・手順を消すときは**確認ダイアログ**を出す。ボタンは縦並びで「やめる」が上・「削除する」が下（**破壊的動作を上に置かない**。Phase 4 と同じ）
- ダイアログに**何を消すのか**を出す（材料なら「しょうゆ 大さじ2」、手順なら「手順3」）
- **全欄が空の行はダイアログを出さずに消す**（失うものが無い）
- 消えるのは画面上の行だけ。**保存するまで DB は変わらない**

**受け入れ基準**

- [ ] 値の入った行の「削除」を押すとダイアログが出て、対象の材料名（手順なら番号）が書かれている
- [ ] 「やめる」/ `Escape` / 背景クリックで閉じ、行が残っている
- [ ] 「削除する」で行が消える
- [ ] 追加したばかりの空の行は、ダイアログ無しで消える

### Req5: 保存できる

決定（段階1）の1・2・4。

- ヘッダー右の「**保存**」で、画面上の材料と手順を**まとめて**保存する
- 保存の前に次の処理をする:
  - **全欄が空の行は捨てる**（材料: 材料名も分量も空。手順: 本文が空）
  - 前後の空白を落とす
  - **材料名が空で分量だけある行は保存しない。** その欄に「未入力」を出して止める
  - 分量が空なら「分量なし」（`null`）として保存する
- 材料0件・手順0件でも保存できる
- 成功したら **S-04 通常モード**（`/recipes/<id>`）へ戻る。**履歴を置き換える**ので、「戻る」で編集画面に戻ってこない
- **二重送信しない**（保存中は保存ボタンを押せない）
- 失敗したら画面に留まり、**入力内容を失わない**。文言は「原因」と「次にすること」が読み取れるもの

**受け入れ基準**

- [ ] 材料名・分量・カテゴリ・手順を変えて保存すると、S-04 に変更が出る。再読み込みしても残っている
- [ ] 空の行を足したまま保存すると、その行は捨てられて保存が通る
- [ ] 材料名を空にして分量だけ残すと、保存されず、その欄に「未入力」が出る
- [ ] 分量を空にして保存すると、S-04 でその材料が分量なしで出る
- [ ] 材料・手順を全部消して保存でき、S-04 に「材料が登録されていません。」「手順が登録されていません。」が出る
- [ ] 保存後に「戻る」を押しても編集画面に戻らない
- [ ] 保存中に保存ボタンを連打しても1回しか送られない
- [ ] 通信を切って保存すると、画面に留まり、入力が残り、文言が出る

### Req6: 未保存の変更を失わせない

`UI_DESIGN.md` S-05「未保存のまま離れようとしたら引き止める」/ 引き継ぎ資料 Interactions「← 中止: 編集中の場合は破棄確認ダイアログ」/ 決定③。

- **`← 中止`** を押したとき、**変更があれば破棄確認ダイアログ**を出す。ボタンは縦並びで「編集を続ける」が上・「破棄する」が下
  - 「破棄する」→ S-04 通常モードへ `replace` で戻る。何も保存しない
  - 「編集を続ける」/ `Escape` / 背景クリック → 閉じて編集に戻る
- **変更が無ければ**、ダイアログ無しでそのまま S-04 通常モードへ戻る
- **変更があるときだけ**、再読み込み・タブを閉じる・URL の直打ちでブラウザの離脱確認（`beforeunload`）が出る
- **ブラウザの「戻る」は止めない**（決定③。既知の制約として design.md に記録する）
- 「変更がある」とは、**保存したときに DB に書かれる内容が、開いた時点と違う**こと。空の行を足しただけ（保存すると捨てられる）は変更に数えない

**受け入れ基準**

- [ ] 何も変えずに `← 中止` を押すと、ダイアログ無しで S-04 に戻る
- [ ] 1文字変えて `← 中止` を押すとダイアログが出る。「編集を続ける」で入力が残っている
- [ ] 「破棄する」で S-04 に戻り、変更が保存されていない
- [ ] 1文字変えて再読み込みすると、ブラウザの離脱確認が出る
- [ ] 何も変えずに再読み込みすると、離脱確認が出ない
- [ ] 空の行を追加しただけで `← 中止` を押すと、ダイアログ無しで戻る
- [ ] 保存に成功したあとの遷移で離脱確認が出ない

### Req7: 他人のレシピは開けず、直せない

`.kiro/steering/architecture.md`「レシピは必ず `userId` でスコープする」。Phase 3・4 と同じ。

- 未ログインで `/recipes/<id>/edit` を開くと `/login` へ
- 存在しないID・他人のレシピIDは**同じ「見つかりません」画面**（区別しない）
- `PUT /api/recipes/<id>` は、未ログインで 401、存在しない / 他人のもので 404。**他人のレシピの材料・手順は1行も変わらない**

**受け入れ基準**

- [ ] 未ログインで `/recipes/<id>/edit` を開くと `/login` へ移る
- [ ] 存在しないIDの `/recipes/<id>/edit` で「レシピが見つかりません」が出る
- [ ] 未ログインで `PUT` を送ると 401
- [ ] 他人のレシピIDに `PUT` を送ると 404 で、そのレシピの材料・手順が変わっていない

## 非機能要件

| 項目           | 内容                                                                                            |
| -------------- | ----------------------------------------------------------------------------------------------- |
| 画面の応答     | 編集画面の表示は1秒以内（`REQUIREMENTS.md` 6.1）。**S-04 と同じ取得1回**                        |
| 保存の一貫性   | **材料と手順は全部入れ替わるか、何も変わらないか。** 途中で失敗して半分だけ消えた状態を作らない |
| タップ領域     | 48px 以上（引き継ぎ資料「タップ領域」）。行カードの入力欄は資料の 52px                          |
| 入力のしやすさ | スマホで分量欄が潰れない（資料の 96px 固定）。手順の入力欄は複数行                              |
| 認可           | **セッションだけを根拠にする。** クライアントが送る `userId` を信用しない                       |

## スコープ外（このフェーズでやらない）

| 項目                           | 理由                                                                           |
| ------------------------------ | ------------------------------------------------------------------------------ |
| タイトルの編集                 | **S-04 の `✎ 改題` で直す**（`REQUIREMENTS.md` 4.7 の線引き）                  |
| 人数（`servings`）の編集       | `REQUIREMENTS.md` 4.7 の編集対象（材料・分量・カテゴリ・作り方）に入っていない |
| 材料・手順の並べ替え           | **決定①**（ユーザー決定）                                                      |
| 写真の差し替え・再解析         | MVP のスコープに無い                                                           |
| ブラウザの「戻る」での引き止め | **決定③。** Next.js 16 に止める API が無い（design.md 1.3）                    |
| 複数タブでの同時編集の調停     | 後から保存したほうが勝つ。想定規模（`REQUIREMENTS.md` 6.1）で起きる頻度が低い  |
| 行削除の「元に戻す」           | 確認ダイアログで代える。保存前なら `← 中止` で全部戻せる                       |
