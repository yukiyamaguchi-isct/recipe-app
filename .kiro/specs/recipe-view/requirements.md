# recipe-view（Phase 3）の要件定義

## 背景

`REQUIREMENTS.md` 4.4 / 4.6 と `UI_DESIGN.md` S-04 / S-04c に対応する。Phase 2 で保存できるようになったレシピを、**読める形で画面に出す**。アプリの中心画面。

Phase 2 の `/upload` は解析・保存まで通るが着地先が無く、「レシピを保存しました。読み取った内容を確認する画面は、次のフェーズで追加します」と出して止まっている（`app/upload/photo-picker.tsx`）。**このフェーズの仕上げは、そこから S-04c へ遷移させること。**

## 前提（確定済み。蒸し返さない）

- 視覚仕様は `Design_引き継ぎ資料/design_handoff_recipe_design_system/README.md` が正。**hifi（ピクセル精度）**で、色・書体・余白・角丸・影・状態はすべて確定値
- **「移動 / 操作 / 絞り込み」を面の有無で描き分ける**のがこのデザインの中核ルール。**この3種以外の見た目をヘッダー・タブに足さない**
- 絞り込みタブの既定は「全体」。**常にどれか1つが必ず点灯する**
- 材料の見出しは `servings` があれば「材料（4人分）」、無ければ「材料」だけ。**取れなかった人数を勝手に丸めた数字で埋めない**（`REQUIREMENTS.md` 9章）
- デザインの `qty` は DB では `amount` が正（`.kiro/specs/recipe-analysis/design.md` 6.2.5）
- ダークモードは MVP では不要。ライト1組に絞る
- 詳細画面と編集画面は**別画面**にする（`UI_DESIGN.md` 4章 決定3）

### ✅ 2026-08-23 のユーザー決定

- **S-04 / S-04c に元のレシピ写真は表示しない。** デザイン原本にも画像は置かれていない（根拠は design.md 1.1）
- したがって**署名付きURLはこのフェーズのスコープ外**。有効期限1時間 / ページ表示時にまとめて発行 / サムネイルは当面作らない、という決定は **Phase 4（recipe-list）向け**として design.md 5.5 に記録する

## 要件

### Req1: 保存したレシピを1件表示できる（S-04 通常モード）

`REQUIREMENTS.md` 4.4 / `UI_DESIGN.md` S-04。

- レシピのタイトル、材料（名前・分量・カテゴリ）、作り方の手順が1画面で読める
- 材料は「野菜 / 調味料 / その他」のカテゴリ見出しごとに積まれる
- 材料も手順も**保存された順序**（`order`）で並ぶ。Claude が返した順序が原文の順序で、材料は買い物の、手順は調理の順になっている
- 分量が無い材料（`amount` が `null`）でも行が欠けない
- 「少々」「適量」のような文字列の分量がそのまま出る

**受け入れ基準**

- [ ] `/recipes/<id>` を開くと、そのレシピのタイトルが画面に出る
- [ ] 保存されている材料が全件表示される（件数が DB と一致する）
- [ ] 保存されている手順が全件、1から連番で表示される
- [ ] `servings` が入っているレシピでは見出しが「材料（4人分）」になる
- [ ] `servings` が `null` のレシピでは見出しが「材料」だけになり、**数字が出ない**
- [ ] `amount` が `null` の材料でも材料名が表示される

### Req2: 材料をカテゴリで絞り込める

`REQUIREMENTS.md` 4.4 / `UI_DESIGN.md` S-04。

- 「全体 / 野菜 / 調味料 / その他」の4タブで絞り込む。**既定は「全体」**
- 絞り込んでもページ遷移せず、スクロール位置も変わらない
- 選択は常に1つ。どれも選ばれていない状態を作らない
- 該当する材料が0件のカテゴリを選んだときに、空白ではなくその旨が出る

**受け入れ基準**

- [ ] 開いた直後は「全体」が選択されており、全カテゴリの材料が見えている
- [ ] 「野菜」を押すと野菜だけになり、調味料・その他の行が消える
- [ ] 絞り込んでも URL が変わらず、作り方セクションの位置もずれない
- [ ] 材料が1件も無いカテゴリを選ぶと、空白ではなく「該当する材料はありません」等が出る

### Req3: 固定ヘッダーから材料・作り方へ移動でき、現在位置が分かる

`REQUIREMENTS.md` 4.4 / `UI_DESIGN.md` S-04。

- ヘッダーは**スクロールしても画面上部に固定される**
- ヘッダーの「材料 ↓」「作り方 ↓」でページ内を移動できる
- **現在位置を反映する。** 作り方までスクロールすると「作り方」が現在位置として示される
- ヘッダーの「移動」と材料タブの「絞り込み」は役割が違うので、**見た目で明確に区別する**（面の有無）

**受け入れ基準**

- [ ] 下までスクロールしてもヘッダーが画面上部に残っている
- [ ] 「作り方 ↓」を押すと作り方セクションが画面上部に来る
- [ ] 作り方までスクロールすると、押していなくても「作り方」が現在位置として示される
- [ ] ヘッダーの移動リンクには面（背景色）が無く、材料タブには面がある

### Req4: 他人のレシピを開けない

`.kiro/steering/architecture.md`「レシピは必ず `userId` でスコープする」。Phase 1 の Req4 が土台。

- 未ログインで開こうとすると `/login` へリダイレクトされる
- ログイン済みでも、**他人のレシピIDを URL に直打ちしたら開けない**
- 「存在しない」と「他人のもの」を**画面上で区別しない**（IDの総当たりで他人のレシピの存在を確かめられないようにする）

**受け入れ基準**

- [ ] 未ログインで `/recipes/<id>` を開くと `/login` にリダイレクトされる
- [ ] 別ユーザーのレシピIDを直打ちすると、内容が表示されない
- [ ] 存在しないIDと他人のIDで、**同じ画面**が出る（文言もステータスも同じ）

### Req5: 解析直後は確認モード（S-04c）に着地する

`REQUIREMENTS.md` 4.6 / `UI_DESIGN.md` S-04c。

- 解析が終わったら、S-03 に留まらず確認モードへ遷移する
- 確認モードは S-04 と**同一の表示**に3点が加わるだけ
  1. 上部に「確認画面 — 内容をチェック」のバナー
  2. 最下部に「この内容で決定」「編集する」（**スマホでは固定表示**）
  3. 「← 一覧」を出さない
- 「決定」で通常モードへ移る
- **どちらを選ぶ前でもレシピは保存済み**（Phase 2 で担保済み。確認画面で離脱しても解析結果を失わない）

**受け入れ基準**

- [ ] `/upload` で解析が成功すると、確認モードの画面に遷移する
- [ ] 確認モードに「確認画面 — 内容をチェック」のバナーが出る
- [ ] 確認モードの最下部に「この内容で決定」「編集する」が出て、スクロールしても隠れない
- [ ] 確認モードに「← 一覧」が出ない
- [ ] 「この内容で決定」を押すと通常モードになり、バナーと最下部バーが消える
- [ ] 確認モードのまま画面を閉じても、あとで同じレシピを開ける

### Req6: 開けないレシピを開いたときに何が起きたか分かる

`REQUIREMENTS.md` 4.3 と同じ方針（白画面やスタックトレースを見せない）。

- 存在しない・他人のものだった場合、日本語の説明と次の行動（戻る導線）が出る
- 内部の情報（ID の生値、DB のエラー、スタックトレース）を画面に出さない

**受け入れ基準**

- [ ] 存在しないIDを開くと、日本語のメッセージと戻る導線が出る
- [ ] その画面に内部情報（例外メッセージ・スタックトレース）が出ない

### Req7: レシピのタイトルをその場で変更できる（✅ 2026-08-24 ユーザー決定で Phase 3 に追加）

`UI_DESIGN.md` S-04「タイトル横の鉛筆アイコンでその場で改名できる（編集画面まで行かせない）」。

- ヘッダーのタイトル横の `✎` を押すと、その場で入力欄に切り替わる
- 変更を確定すると保存され、画面のタイトルが変わる
- **他人のレシピのタイトルは変更できない**（Req4 と同じスコープ）
- 空のタイトルは保存できない
- 保存に失敗したときは、何が起きたか分かる

**受け入れ基準**

- [ ] タイトル横の `✎` を押すと入力欄になる
- [ ] 変更して確定すると、画面のタイトルが新しいものになる
- [ ] 再読み込みしても変更が残っている
- [ ] 空にして確定しようとすると保存されず、その旨が出る
- [ ] 他ユーザーのレシピIDに対して更新を送ると拒否される
- [ ] 未ログインで更新を送ると 401 が返る

## 非機能要件

- **画面表示の応答時間は1秒以内**（`REQUIREMENTS.md` 6.1）。1レシピの取得で複数回 DB を往復しない
- PC・スマホの双方で崩れない。**一覧以外の画面は単一カラムのまま max-width 640px で中央寄せ**（デザイン資料の Responsive）
- 本文の最小サイズは 17px、タップ領域は最小 48×48px、主要ボタンは 56px
- **コントラスト 4.5:1 以上。** `--color-accent`（`#00C6D7`）の上に文字を置かない
- `prefers-reduced-motion` の指定を尊重する（`app/globals.css` に既にある）
- 将来の React Native 移植のため、`border` / `border-radius` / `box-shadow` / `flex` / `grid` だけで組む。グラデーションや `backdrop-filter` に依存しない
