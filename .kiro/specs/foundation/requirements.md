# foundation（Phase 0）の要件定義

## 背景

機能実装に入る前に、動作する Next.js プロジェクトと Neon への DB 接続を用意する。この段階で「ローカルで動く」「マイグレーションが通る」ことを確認しておかないと、以降のフェーズで問題の切り分けができなくなる。

このフェーズにユーザー向け機能は含まない。土台だけを作る。

## 要件

### Req1: Next.js プロジェクトが起動する

- `npm run dev` でローカルサーバーが起動し、ブラウザでページが表示される
- TypeScript が有効で、型エラーがビルド時に検出される
- Tailwind CSS のクラスが実際に反映される

**受け入れ基準**

- [ ] `npm run dev` 実行後、`http://localhost:3000` にアクセスして画面が表示される
- [ ] `npm run build` が成功する
- [ ] Tailwind のユーティリティクラスを書いたら見た目が変わることを目視で確認できる

### Req2: Neon に接続でき、マイグレーションが実行できる

- Prisma 経由で Neon の PostgreSQL に接続できる
- `DATABASE_URL`（プール接続）と `DIRECT_URL`（直接接続）の2本立てになっている
- マイグレーションを実行するとテーブルが実際に作成される

**受け入れ基準**

- [ ] `npx prisma migrate dev` が成功し、Neon 上にテーブルが作成される
- [ ] `npx prisma studio` でテーブルの中身を確認できる
- [ ] Neon のコンソール上でもテーブルが見える

### Req3: 開発ツールが動く

- ESLint と Prettier が設定され、コマンドで実行できる
- Vitest が設定され、サンプルテストが通る

**受け入れ基準**

- [ ] `npm run lint` が実行でき、意図的なエラーを検出する
- [ ] `npm run format` でコードが整形される
- [ ] `npm run test` でサンプルテストが成功する

### Req4: 環境変数の枠組みがある

- 必要な環境変数が `.env.example` に列挙されている
- `.env` は git 管理外である
- 環境変数が欠けている場合、起動時に分かりやすいエラーになる

**受け入れ基準**

- [ ] `.env.example` に必要な変数がすべて列挙されている
- [ ] `git status` に `.env` が出てこない
- [ ] `DATABASE_URL` を空にすると、原因が分かるエラーメッセージが出る

## 非機能要件

- **秘密情報をコードに直書きしない。** すべて `.env` 経由
- **ローカルファイルシステムに永続データを書かない。** Vercel の関数には永続的な書き込み可能ファイルシステムがないため

## スコープ外

以下はこのフェーズに含めない。

- 認証の実装（Phase 1）
- 画像アップロード・解析（Phase 2）
- 画面のデザイン（`DESIGN.md` の完成を待つ）
- Vercel へのデプロイ（動作確認できる段階になってから）
