# recipe-list（Phase 4）の要件定義

## 背景

保存したレシピを読む画面（S-04）は Phase 3 でできたが、**そこへ辿り着く方法が URL の直打ちしか無い。** 解析直後は `/upload` から確認モードへ流れ込むので1枚目は読めるが、**2枚目を撮ったあと1枚目に戻る手段が無い。**

このフェーズで S-02（レシピ一覧）を作り、`app/page.tsx` の暫定ホームを置き換える。あわせて、Phase 3 で保留していた **S-04 のヘッダー上段（`← 一覧`）を戻す**。

## 前提（確定済み。蒸し返さない）

- **視覚仕様は `Design_引き継ぎ資料/design_handoff_recipe_design_system/README.md` が正。** 正本の HTML は `Recipe Design System v2.dc.html`（緑基調の無印版は履歴。使わない）
- **デザイントークンは `app/globals.css` の `@theme` に投入済み。値を推測で変えない**
- **「移動 / 操作 / 絞り込み」を面の有無で描き分ける。この3種以外の見た目を足さない**（design.md 6.2）
- **レシピは必ず `userId` でスコープする**（`.kiro/steering/architecture.md`）
- **一覧だけが 1列（〜767px）/ 3列（768px〜）。他の画面は単一カラムのまま max-width 640px で中央寄せ**（引き継ぎ資料 Responsive / recipe-view design.md 食い違い5）
- 詳細画面と編集画面は別画面（`UI_DESIGN.md` 4章 決定3）

## 要件

### Req1: 保存したレシピを一覧できる（S-02）

`REQUIREMENTS.md` 4.7 / `UI_DESIGN.md` S-02。**ログイン後のホーム（`/`）がこの画面になる。**

- 自分が保存したレシピがカードで並ぶ。カードにはサムネイル・タイトル・作成日が出る
- **新しいものが先頭**（`createdAt` の降順）。直前に撮ったレシピが一番上に来る
- タイトルは**2行まで**。それ以上は省略する（長いタイトルでカードの高さが崩れないように）
- ヘッダーに保存件数が出る
- **カード全面がタップ領域**。カードを押すと `/recipes/<id>`（通常モード）へ移動する

**受け入れ基準**

- [ ] `/` を開くと、保存済みのレシピが全件カードで並ぶ（件数が DB と一致する）
- [ ] 並び順が新しい順になっている（直前に解析したレシピが先頭）
- [ ] カードにタイトルと作成日が出る。作成日の形式が「2026年8月12日」
- [ ] カードのどこを押しても `/recipes/<id>` へ移動する（タイトルの文字の上だけではない）
- [ ] タイトルが3行以上になるレシピでも、カードの高さが他と揃っている
- [ ] ヘッダーの件数が実際のカード枚数と一致する

### Req2: 一覧にレシピの写真が出る

`REQUIREMENTS.md` 4.7。**このフェーズで初めて S3 の画像を画面に出す。**

- `Recipe.imageKey` は S3 のオブジェクトキーであって URL ではない。**バケットは非公開**なので、キーからURLを組み立てても表示できない
- **表示のたびに署名付きURLを発行する。** 有効期限は1時間
- **発行した URL をDBに保存しない**
- 発行はページ表示時にまとめて行う（Server Component が全件分を一度に作って渡す）
- 画像が読めなかったカードでも、タイトルと作成日は読めて、レシピを開ける

**受け入れ基準**

- [ ] 一覧を開くとカードに写真が出る
- [ ] ページのHTMLに含まれる画像URLに `X-Amz-Signature` と `X-Amz-Expires` が付いている
- [ ] `X-Amz-Expires` の値が `3600`
- [ ] DB の `Recipe` テーブルに署名付きURLが保存されていない（`imageKey` のまま）
- [ ] 画像URLを削って開くなど、署名の無いURLでは画像が取得できない（403）
- [ ] 画像が取得できないカードでも、タイトル・作成日が出てレシピを開ける

### Req3: レシピが1件も無いときに何をすればよいか分かる

`UI_DESIGN.md` S-02「空状態の画面を用意する」。**初回ユーザーが必ず通る。**

- レシピが0件のとき、空のリストではなく**空状態**を出す
- 「レシピなし」という見出しと、何をすれば並ぶのかの説明が出る
- **そこから直接アップロードへ行ける**

**受け入れ基準**

- [ ] レシピが0件のアカウントで `/` を開くと、空状態が出る
- [ ] 空状態に「レシピなし」の見出しと説明文が出る
- [ ] 空状態のボタンを押すと `/upload` へ移動する
- [ ] レシピを1件保存すると空状態が消え、カードに変わる

### Req4: 一覧から新しい写真を撮りに行ける

`UI_DESIGN.md` S-02「追加ボタンを常に見える位置に置く」。

- スマホでは右下に固定の丸ボタン（FAB）を置く。**スクロールしても常に見えている**
- FAB を押すと `/upload`（S-03）へ移動する
- PC ではヘッダー右に「＋ 新規」を置く

**受け入れ基準**

- [ ] スマホ幅で一覧を開くと右下に FAB が出る
- [ ] カードが画面を超える件数でも、下までスクロールした状態で FAB が見えている
- [ ] FAB を押すと `/upload` へ移動する
- [ ] FAB が最後のカードの内容を隠していない

### Req5: 保存したレシピを削除できる

`REQUIREMENTS.md` 4.7 / `UI_DESIGN.md` S-02「削除は一覧・詳細の両方から可能。確認ダイアログを挟む」。

**このフェーズでは一覧からの削除だけを作る**（S-04 からの削除はスコープ外。下記）。

- **必ず確認ダイアログを挟む。** 押し間違いで消えない（引き継ぎ資料 Interactions「削除: 常に確認ダイアログを経由」）
- ダイアログにはどのレシピを消すのかが出る
- 削除するとレシピ本体・材料・手順が消える
- **S3 に保存した画像も消す**（2026-08-25 ユーザー決定）
- 削除後は一覧に戻り、そのレシピが消えている

**受け入れ基準**

- [ ] カードの削除操作から、いきなり消えずに確認ダイアログが出る
- [ ] ダイアログに対象のレシピのタイトルが出る
- [ ] 「やめる」でダイアログが閉じ、**レシピが残っている**
- [ ] 「削除する」でレシピが一覧から消える
- [ ] 再読み込みしても消えたままになっている
- [ ] DB から `Recipe` / `Ingredient` / `Step` が消えている
- [ ] S3 から該当の画像が消えている
- [ ] 最後の1件を削除すると空状態に変わる

### Req6: 他人のレシピが見えない・消せない

`REQUIREMENTS.md` 4.1 /`.kiro/steering/architecture.md`「レシピは必ず `userId` でスコープする」。

- 一覧には自分のレシピだけが出る
- 他人のレシピIDを指定して削除しても、**消えない**
- 削除できなかったとき、「存在しない」と「他人のもの」を**区別しない**（Phase 3 の Req4 と同じ理由。IDの総当たりで他人のレシピの存在が分かってしまう）

**受け入れ基準**

- [ ] 別ユーザーでログインすると、そのユーザーのレシピだけが並ぶ
- [ ] 他ユーザーのレシピIDに削除リクエストを送ると 404 が返り、**そのレシピが消えていない**
- [ ] 存在しないIDに削除リクエストを送っても、他人のIDのときと同じ応答になる
- [ ] 未ログインで削除リクエストを送ると 401 が返る
- [ ] 未ログインで `/` を開くと `/login` へ移動する

### Req7: レシピ表示から一覧へ戻れる（Phase 3 からの持ち越し）

`UI_DESIGN.md` S-04 /`.kiro/specs/recipe-view/requirements.md` 決着3。**Phase 3 では遷移先が無いため出していなかった。**

- S-04 の固定ヘッダーに上段が戻り、左に `← 一覧` が出る
- `← 一覧` を押すと `/`（S-02）へ移動する
- **確認モード（S-04c）では `← 一覧` を出さない**（`UI_DESIGN.md` S-04c。デザインHTMLのモックには描かれているが README が正）
- **`編集` は Phase 5 のまま出さない**（決着2）
- 開けないレシピの画面（`not-found.tsx`）の戻り先も一覧になる

**受け入れ基準**

- [ ] 通常モードの S-04 に `← 一覧` が出る
- [ ] `← 一覧` を押すと `/` へ移動する
- [ ] 確認モード（`?confirm=1`）では `← 一覧` が出ない
- [ ] 通常モード・確認モードのどちらでも `編集` が出ない
- [ ] 上段が戻っても、アンカー移動の着地点が固定ヘッダーの下に潜らない（**タイトルが2行のときも**）
- [ ] 存在しないIDを開いたときの画面から一覧へ戻れる

### Req8: 一覧からログアウトできる

`UI_DESIGN.md` S-01「ログアウトはヘッダーのメニューに置く」。**暫定ホームを置き換えるとログアウトの導線が消えるため、このフェーズで移設する。**

- 一覧ヘッダーの右端にログアウトが出る
- 押すとログアウトし、`/login` へ移動する
- ログアウト後に `/` を開くと `/login` へ戻される

**受け入れ基準**

- [ ] 一覧ヘッダーにログアウトが出る
- [ ] 押すとログアウトされ、`/login` に着地する
- [ ] ログアウト後に `/` を直接開くと `/login` へリダイレクトされる

## 非機能要件

- **一覧の表示は1秒以内**（`REQUIREMENTS.md` 6.1）。署名の計算はローカルで完結し AWS への通信は発生しないため、全件分をまとめて発行しても往復は増えない
- PC・スマホの双方で崩れない。**一覧だけが 1列（〜767px）/ 3列（768px〜）**
- 最小タップ領域 48px（`--size-tap`）を守る
- 将来の React Native 移植のため、`border` / `border-radius` / `box-shadow` / `flex` / `grid` だけで組む
- **スキーマ変更なし。** `Recipe.createdAt` も `@@index([userId])` も既にあり、`Ingredient` / `Step` は `onDelete: Cascade`。**マイグレーションは発生しない**

## スコープ外

- **S-04（詳細画面）からの削除** — `UI_DESIGN.md` S-02 は「一覧・詳細の両方から可能」としているが、S-04 の削除ボタンはヘッダー上段の `編集` と同じ場所を争う。**Phase 5 で `編集` を戻すときに、あわせて置き場所を決める**
- **サムネイル用の小画像の生成** — 実機の体感を見てから判断する（2026-08-23 決定）。一覧は正規化済み（長辺2576px / 品質85、約500KB〜1MB）の画像をそのまま出す
- **ページング・無限スクロール** — 想定登録ユーザー10人・月100回の規模では過剰（`REQUIREMENTS.md` 6.1）。件数が増えて実際に遅くなってから入れる
- **一覧の検索・並べ替え・絞り込み** — MVPスコープ外（`REQUIREMENTS.md` 3章）
- **S-05 レシピ編集**（材料・分量・カテゴリ・手順の修正） — Phase 5
- **確認モードの `[編集する]` ボタン** — Phase 5。遷移先の S-05 が無い（`.kiro/specs/recipe-view/design.md` 6.8）
- **S-01（ログイン）をデザインシステムに合わせる作業。** `app/globals.css` の `@theme inline`（`--color-background` / `--color-foreground`）の削除もそのとき。**ただしホームは本フェーズで S-02 に置き換わるので、この2トークンの利用者は S-01 だけになる**
