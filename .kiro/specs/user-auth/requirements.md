# user-auth（Phase 1）の要件定義

## 背景

`REQUIREMENTS.md` 4.1 と `UI_DESIGN.md` S-01 に対応する。Google アカウントでログインできるようにし、以降のフェーズで作るレシピをユーザーごとに紐づけられる状態にする。

このフェーズで扱うのはログイン・ログアウトと、セッションから `userId` を取り出す仕組みまで。レシピに関する機能は含まない。

## 前提（確定済み。蒸し返さない）

- 認証は **Auth.js（NextAuth v5）+ Google provider** のみ。メール＋パスワードは採らない
- session strategy は **`jwt`**。将来モバイルアプリから叩く際に Cookie ベースだと作り直しになるため（`REQUIREMENTS.md` 6章）
- パスワードは保持しない
- ビジュアルデザインの完成を待たずに着手する。S-01 はボタン1つの画面のため

## 要件

### Req1: Google アカウントでログインできる

- S-01 に「Googleでログイン」ボタンが1つある。入力フォームは無い
- 押すと Google の同意画面に遷移し、承認するとアプリに戻ってログイン済みになる
- 初回ログイン時にユーザーが自動作成される。新規登録という別操作は無い
- 何のアプリか分かる説明を1〜2行添える（説明なしに Google の認証を求めない）

**受け入れ基準**

- [ ] 未ログインで `/login` を開くと「Googleでログイン」ボタンが表示される
- [ ] ボタンを押すと Google の同意画面に遷移する
- [ ] 承認するとアプリに戻り、ログイン済みの状態になる
- [ ] 初回ログイン後、DB の `User` と `Account` にレコードが1件ずつ作られている
- [ ] 同じアカウントで2回目にログインしても `User` が増えない

### Req2: ログアウトできる

- ログイン済みのとき、画面から自分の名前が確認でき、ログアウトできる
- ログアウトすると未ログイン状態に戻り、保護されたページを開けなくなる

**受け入れ基準**

- [ ] ログイン済みのときログアウト操作が画面上にある
- [ ] ログアウト後に保護されたページを開くと `/login` に飛ばされる

### Req3: 未ログインでは保護されたページを開けない

- 認証が要るページに未ログインでアクセスすると `/login` へリダイレクトされる
- 逆に、ログイン済みで `/login` を開いたらホームへ送る

**受け入れ基準**

- [ ] 未ログインでホームを開くと `/login` にリダイレクトされる
- [ ] ログイン済みで `/login` を開くとホームにリダイレクトされる

### Req4: サーバー側でセッションから `userId` を取得できる

以降のフェーズが依存する土台。`.kiro/steering/architecture.md` の「クライアントから渡された `userId` を信用しない」を実現する。

- Server Component と Route Handler の両方から、ログイン中のユーザーの `id` を取得できる
- 未ログインのときは明確に失敗する（`null` を握り潰して先に進まない）
- JWT に載せる `userId` は DB の `User.id` と一致する

**受け入れ基準**

- [ ] Server Component からログイン中の `userId` を取得できる
- [x] Route Handler から同じ `userId` を取得できる（Phase 2 段階8。`POST /api/recipes/analyze`）
- [x] 未ログインで Route Handler を叩くと 401 が返る（Phase 2 段階8。`__tests__/analyze-route.test.ts`）
- [ ] 取得できる `userId` が DB の `User.id` と一致する

### Req5: ログインに失敗したときに何が起きたか分かる

`UI_DESIGN.md` S-01 の「原因と次の行動を書く」に対応する。

- Google 側でキャンセルした場合、その旨と次の行動が画面に出る
- 設定不備などの失敗でも、白画面やスタックトレースを見せない

**受け入れ基準**

- [ ] Google の同意画面でキャンセルすると、日本語のメッセージと再試行の導線が出る

## 非機能要件

- `AUTH_SECRET` / `AUTH_GOOGLE_ID` / `AUTH_GOOGLE_SECRET` は `.env` から読む。コードに直書きしない
- 認証まわりのエラーメッセージに、内部の値（トークン・シークレット）を含めない
- PC・スマホの双方で崩れないレイアウトにする（`REQUIREMENTS.md` 6章）

## スコープ外

- レシピ一覧（S-02）の中身 — Phase 4。このフェーズではログイン後の着地先として最小限のホームだけを置く
- 画像アップロード・解析 — Phase 2
- ビジュアルデザインの適用 — Phase 3 の直前に合流する
- Google 以外のプロバイダ、アカウント連携、退会機能
- メール認証（Email provider）。使わないため `VerificationToken` も作らない
