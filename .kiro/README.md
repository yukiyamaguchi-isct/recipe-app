# .kiro

このプロジェクトの「記憶」を置く場所。Kiroフレームワーク（`kiro-personal-app-guide.md` 参照）に沿った構成。

```
.kiro/
├── steering/          # プロジェクト全体の設計方針。更新頻度は低い
│   ├── tech-stack.md
│   └── architecture.md
└── specs/             # 機能ごとの仕様。フェーズを開始するときに作る
    └── <feature>/
        ├── requirements.md  # 何が必要か
        ├── design.md        # どう実装するか
        └── tasks.md         # 何をやるか（チェックリスト）
```

## 上位文書との関係

| 文書                     | 役割                                                |
| ------------------------ | --------------------------------------------------- |
| `REQUIREMENTS.md`        | アプリ全体の要件。MVPスコープと後続フェーズの線引き |
| `UI_DESIGN.md`           | アプリ全体の画面設計                                |
| `.kiro/steering/`        | 実装方針。技術選定とアーキテクチャ                  |
| `.kiro/specs/<feature>/` | 機能単位の仕様。上3つを踏まえて具体化する           |

`specs/` は**フェーズ着手時に作る**。全機能分を先に書かない。仕様と実装がズレたら実装に合わせて仕様を更新する（Kiroの目的は「仕様が絶対」ではなく「プロジェクト記憶の同期」）。
